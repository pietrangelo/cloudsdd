# RFC 007: AWS Relational Database Implementation

- **Status:** Approved (2026-08-01), implemented
- **Author:** Claude (Senior Staff Cloud Platform Engineer, AI-assisted)
- **Date:** 2026-08-01
- **Depends on:** [RFC 002](002-aws-provider.md),
  [RFC 006](006-cli-entrypoint.md)

## 1. Context and Problem Statement
With the Natural Language CLI and engine pipeline fully operational, CloudSDD can now orchestrate cloud deployments. However, the AWS provider currently only implements `object_storage` and `cross_account_role`. We need to support the `relational_database` resource type to allow users to deploy secure, production-ready databases via natural language.

Crucially, the system mandate requires that CloudSDD enforce "best state-of-the-art implementations based on the cloud provider spec" invisibly to the user.

## 2. Proposed Architecture & Schema

### 2.1 Specification Properties
The `properties` object for a `relational_database` will strictly expect:
```json
{
  "engine": "postgres", // e.g., postgres, mysql, aurora-postgresql
  "version": "15",
  "high_availability": true
}
```

### 2.2 Enforced State-of-the-Art Defaults
When the AWS Provider (via Pulumi) translates these properties into AWS RDS resources, it will hardcode and enforce the following best-practices:
1. **Private by Default**: `PubliclyAccessible = false`. The database will only be accessible from within the VPC.
2. **Encryption at Rest**: `StorageEncrypted = true` using AWS KMS.
3. **Automated Backups**: Enabled by default (e.g., 7-day retention period).
4. **IAM Authentication**: `IAMDatabaseAuthenticationEnabled = true` to prevent reliance on static passwords where possible.
5. **High Availability**: If `high_availability` is `true`, it will enforce `MultiAZ = true`.
6. **Storage Auto-Scaling**: Enabled by default to prevent "storage full" downtime.
7. **Performance Insights**: Enabled for advanced monitoring.

## 3. Implementation Steps
1. Create `internal/provider/aws/database.go`.
2. Implement `decodeRelationalDatabaseProperties()` to safely parse the generic JSON properties into a typed Go struct.
3. Implement `declareRelationalDatabase(ctx, ...)` using Pulumi's `aws/rds` package to provision the AWS RDS Instance with the above constraints.
4. Wire it into `Validate()`, `Plan()`, and `Apply()` in `provider.go`.

## 4. Security Considerations
- **No public IP**: Prevents direct internet access.
- **Mass Assignment**: Strict Go structs ensure that users cannot bypass the `PubliclyAccessible = false` default by injecting unexpected fields via the LLM.
- **Passwords**: The initial master password will be randomly generated by Pulumi's `random.RandomPassword` resource and stored safely in the Pulumi state (which itself should be encrypted), rather than being passed in plaintext through the CLI.
