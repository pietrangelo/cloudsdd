# CloudSDD Implementation Plan: RFC 019 (Rosette Consolidation) + RFC 018 remainder

Ordered per [RFC 019](docs/rfc/019-rosette-consolidation.md) §6, so the
in-flight RFC 018 Azure work is written **once** against the final shape.

**Already complete and not repeated here:** RFC 018's data model, Dockerfile
generator, dependency graph, and the AWS and GCP providers end to end. That
record lives in `docs/rfc/018-build-pipeline.md` and in git history; the three
Azure items and the Volumes and Documentation sections below are what remained
unchecked when RFC 019 was approved.

Items are ordered tests-first per `<todo_policy>`, which means a test item may
leave its package not compiling until the implementation item that follows it —
the precedent RFC 018 set at its Azure step. Every **implementation** item must
leave the tree compiling and `go test ./... -count=1` green.

RFC 019 §5's decisive rule: existing provider tests pass with **no assertion
modified** — the sole permitted edit is `ErrPipelineNotResolved` →
`pipeline.ErrNotResolved`. A test needing a changed expectation means behaviour
moved, which this refactor is not permitted to do.
